# Decisions

- The game stays native C++20 + raylib, with an isometric open world and chunk streaming.
- All player-facing content is English.
- NPC interactions are authored lore, concrete quest offers, quest turn-ins, trade and teaching. Unbounded model conversations are removed from the gameplay loop. Quest rewards and conditions are authoritative game rules.
- Clothing and weapons use counted copies. Citizen equipment is reserved from the same inventory; assigning gear does not destroy it. Player equipment changes are available anywhere. Weapon durability is intentionally absent.
- New campaigns select a starting background with real positive and negative modifiers. Existing saves use the neutral Traveler background.
- Strategic warfare stays a placeholder. Citizen jobs, equipment, training and economic contributions are implemented foundations; they must not be presented as marching armies or city conquest.
- Windowed launch is the default even if an old settings file stored fullscreen. Explicit CLI `--fullscreen` or the settings toggle can opt into fullscreen during the session.
- Keep the 60 FPS target. A p95 of 30 ms is a ceiling for richer visuals, not a deliberate frame-rate target.

- New resident research checks all requirements before spending coins. Average trust excludes owned towns so the starting town's guaranteed trust cannot bypass diplomacy. Civic charter earned through exploration unlocks higher diplomatic training.
- Existing leather armor is migrated to a counted garment with its original approximate damage reduction (12 damage → 7, 18 → 11). New heavy guard armor trades movement speed for stronger protection.
- A `--benchmark-community` scenario exercises quest turn-in, clothing copies, resident research, worker assignment, defender equipment and the existing combat/water expedition. Ordinary game sessions never make language-model requests.
- `scripts/run.sh` is the joint local launcher. Wait for a healthy server with alias `forest-npc`, preserve externally owned servers, and terminate only launched children on exit/signals. Model/server downloads and builds remain explicit setup steps. Launching the model does not restore unbounded NPC conversations.
- An explicitly supplied `--llm-port` overrides persisted menu settings, including the default value 8080. The launcher passes one port to both processes.
- Interface text uses a 1.25 multiplier over the previous minimum-16 sizing, rounded to physical integer sizes. Bake the required glyph sizes directly and snap text positions to whole pixels; avoid scaling a nearby font atlas. Wrapping and measurement use the same effective sizes.
- Lessons expose shared authoritative learned/readiness/practice state in both the hall and skills menu. Learning is a one-time unlock, not an XP level; learned lessons disable repeat actions and show completion immediately.
- Main-menu backgrounds are native raylib landscapes (forest lake, coast, town and underwater). Choose once per menu entry and avoid consecutive repeats within a process; FRONTIER_MENU_SCENE can select a scene for reproducible previews. No bitmap downloads or model generation are needed.
- ESC closes an active gameplay panel, otherwise opens/resumes pause. Paused sessions suspend player actions, combat and world/resident simulation. Pause Quit saves successfully before returning to the lobby; on write failure keep the session open for retry. ESC in the lobby never closes the application; the explicit main-menu Quit does. Interactive --play and temporary sessions also return to the lobby, while benchmark/frame-limited automation keeps its existing completion behavior.
- Movement supports both WASD and arrow keys. Combine equivalent directions as booleans before normalization so holding both bindings does not double speed. Reserve WASD for movement; town-hall/diplomacy uses P, settings application uses F5, and E talks to NPCs only, even beside a hall. Menu navigation still uses arrows.
- Saved-world and paused-world summaries share one renderer and five tabs. Inventory and knowledge use vertical rows; individual PNG icons are packed into one texture atlas. Paused summaries read current live progress and cannot teach, research, spend resources or change the player's world layer.
- The dependency graph distinguishes activity counters from learned skills, includes both research prerequisites and quest/town knowledge sources, and uses the authoritative lesson/research readiness checks. Learned cells are light green; locked cells are dark green; ready unlocks get a gold marker. Activity cards show recorded counts, with each child retaining its own threshold.
- Public setup uses scripts/install.sh for a Release game build and tests; --with-model explicitly adds CPU llama-server and the Qwen GGUF download. Keep the existing joint-launch default, with --no-model available for ordinary authored gameplay. Setup never installs system packages or replaces saves/settings. Preserve completed downloads; resume interrupted model downloads in a .part file and promote only after curl succeeds and a GGUF header is present. This is format validation, not a cryptographic checksum.
- Disable both llama.cpp UI building and prebuilt UI downloads for the server setup; the game uses its HTTP API and does not require an additional web frontend. Existing source checkouts remain user-controlled. The English README documents implemented gameplay and links to the incomplete-systems inventory rather than presenting prototypes as complete warfare or city simulation.
- Repository publication targets https://github.com/kiquxd/forest-frontier on main. Keep generated builds, downloaded dependencies/fonts/models, local saves/settings/logs and credentials out of Git; ship sources, content, icon assets and font license. Document full setup with --with-model and the smaller authored-gameplay setup separately. Custom instruction/chat GGUFs can use the same forest-npc alias and streaming API, but compatibility depends on llama.cpp support, the embedded template and current reasoning/sampling parameters; only the default Qwen model is validated.
- README Current limits is the public inventory of all incomplete systems and technical limitations, synchronized with ai/PLACEHOLDERS.md. Keep current behavior and missing parts explicit, preserve the four requested main README sections, and update public/maintainer documentation in the same implementation change. Intentional choices are not missing features; possible extensions are not promises.
- TODO.md is a tracked, removable checklist synchronized with both incomplete-system inventories. Remove only fully implemented/validated scope, splitting partially completed items. Adopt Google C++ Style Guide for new/changed code, with the root Google-based .clang-format and documented .cpp/.hpp/exception-policy adaptations. Style policy and source migration are separate changes; adding configuration alone does not establish source compliance.
- First-party C++ source/test style migration is now implemented in its own change: Google formatting with control-flow braces, consistent function/member/constant names, expanded declarations, direct includes, header guards and explicit namespace qualification. Use scripts/format.sh or --check for src/*.cpp, src/*.hpp and tests/*.cpp only; dependency sources keep upstream conventions. Serialized strings, content IDs, enum numeric order, mechanics and save schema are preserved. Development formatting needs clang-format >=15; validation uses 23.1.3.
- Per user scope, performance measurement coverage and future FPS guarantees are not checklist placeholders. The final inventory category covers release/distribution limitations; gameplay balance limitations remain in the relevant quest/progression sections. Performance targets and required validation remain development rules and Tech Stuff documentation.

- Session management and progression use distinct paused screens: Esc handles Resume/Save/Save & return/Settings; the rebound Progress action (K by default) handles Overview, map, resources, discovered towns and the existing dependency tree. There is no separate skill list. Lobby previews share these views but never mutate saves or trigger live unlocks.
- Base training and resident research use their authoritative checks from the tree. Town technologies and quest knowledge retain visit/completion requirements. Owned-town roster assignments use AssignCitizen and counted equipment, not UI-local mutations.
- Resource discovery records goods acquired at least once. Save v6 adds known_goods and a bounded 512-event history with wall-clock timestamps; it loads v1-v5 without resetting progress and backs up an older original before its migration write. Legacy resource knowledge is inferred from stock/activity where possible; historical events cannot be reconstructed.
- File workflows stay in the lobby after the live World worker is destroyed. Import/copy/export validate the original; rename/copy/import/recovery choose a free slot name, exports refuse existing destinations, and recovery restores a new world while retaining the backup/trash source. A failed preferences write after a successful world operation must not offer a duplicate operation retry.
- Gameplay keys have persisted primary/alternate bindings and explicit conflict swaps. Reserved menu keys remain stable. Shared lobby/pause settings provide text scale and tree contrast; contextual footer keycaps reflect actual bindings. Font atlases cover matching integer sizes, and graph/roster row heights adapt to larger text.
- Basic gamepad actions, left-stick movement and directional menu navigation are included as groundwork. Full controller mapping/remapping/text entry and complete accessibility remain documented limitations; no physical gamepad validation is claimed. Normal authored gameplay has no obsolete model-conversation setting.

- Per the user's current scope, collision geometry remains 2D; autonomous routes/army movement are deferred behind command systems for owned/foreign residents and professions. Existing timer-based job assignments are not that command system. Navigation is a separate inventory category; bounded debug auto-routing remains unchanged apart from shared collision/vessel compatibility.
- Geometry uses explicit circles, boxes, thick segments and polygons; building bases invert the actual four atlas plinth corners, with a box broad phase. Local contacts and substepped sliding change collision response only. Ships remain owned travel modes, with new stable numeric IDs 4-9 and retained legacy IDs 1-3. Prestige represents cost/presentation/travel capability, not a new diplomatic bonus.
- Exploration records fixed world-space sight with building/wall occlusion and shorter forest range. Window/zoom independence preserves old explored cells. Runtime visibility is recomputed and is not serialized. Notes are manual, capped at 128, and stored in v7 alongside new vessel ownership; v1-v6 writes preserve migration backups.
- Authored synthesized audio ships in the repo with a reproducible standard-library generator: three original background loops and twelve effects. Automatic music follows terrain; manual choices, Off and independent volume persist in settings. An unavailable audio device does not prevent gameplay. Nearby hits/wolves/fires have distance attenuation and stereo pan; full spatial/ambient mixing remains unfinished.

### Proportional validation (2026-10-14)

- Routine iteration uses the affected core checks and one final CTest run. Real-window checks focus on the changed interaction; world-smoke defaults to a short journal/save check, with the full flow behind --extended.
- Long idle simulations and repeated percentile analysis are not mandatory after cosmetic or small reversible changes. Performance profiling is reserved for observed slowdowns or credible new load, starting with one 5–10 second sample. Longer scenarios remain available for specific regressions and releases.

## 2026-10-14 — Town infrastructure, crafting limits and local losses

- Successful craft outputs remain immediate but start one persistent global cooldown: rarity tiers take 1/5/30/60/120 simulation minutes. Reopening menus/reloading cannot reset it; offline wall time does not advance it. Ordinary equipment swaps remain unrestricted.
- Crafting requires the appropriate facility on the player's current town territory or through a graph of fully built roads with peaceful accessible towns. New home towns receive a workbench; foreign towns receive seeded facilities. Construction builds six activity types and expands circular territory; basic hall lessons bootstrap this without a school, while resident research/training needs a school. Existing save progression is preserved in schema v8 with migration backups.
- Roads are player-selected complete polylines, not generated inter-town links. Full exploration, endpoints, permissions and the full wood/stone cost are checked before committing; water sections count as more expensive walkable bridges. Navigation/orders remain a separate deferred prerequisite-dependent scope.
- Local defenders can die or, against hostile human guards, deterministically enter captivity (40% of seeded outcomes). Dead entries remain tombstones and lose assigned weapon/clothes; captive copies stay reserved, and ransom returns the same equipment. Player death destroys the equipped weapon; player captivity and strategic army casualties are still absent.
- Surrender creates tribute without annexing the town: 30 coins initially, 10 per 120 simulation seconds, 300 to exit. Missed payment ends the pact and restores local hostility. Returning to a previous ruler restores the recorded pre-union owner; the starting home town previously belonged to the player. No autonomous invasion, transport or occupation simulation is introduced.

## 2026-10-14 — Explicit settings Apply button

- The shared settings/controls panel uses a prominent top-right Apply button. F5 no longer applies settings and is available for gameplay rebinding. Saving remains atomic; draft settings do not become active before Apply.


### Resident-controlled state and city economy (2026-10-15)

This revision supersedes earlier hero/NPC-quest/global-cooldown/passive-job descriptions above. New campaigns and normal legacy play initialize resident control; explicit legacy benchmark fixtures retain their isolated mechanics.

- There is no separate hero. The selected active owned resident supplies the compatibility `Save.player/inventory/health` view; synchronize it before switches/save snapshots. Per-resident bags own counted gear, while state knowledge/maps are shared and goods/product warehouses belong to cities. Never allocate the selected view as an extra equipment owner.
- State management centralizes residents, stocks, production, projects, trade orders, towns and growth. Town halls reuse the same records. K focuses on knowledge; saved-world summaries retain useful read-only tabs. All management pauses simulation; close it to progress production. Health remains in the live HUD, resource lists move into management.
- City projects replace NPC quest issuance and never mint coins. Foreign orders reserve actual buyer funds; delivery consumes resident cargo and transfers escrow to the state. Abandonment refunds once. Unaccepted deficits expire. Intro/specialist/survey knowledge projects can reappear after abandonment, so progression is not permanently blocked.
- Timed physical-workshop queues reserve warehouse inputs/fees, serialize eight jobs per building and run independently across buildings. Rarity delays are 1/5/30/60/120 simulation minutes. Forge cap is max(1, active population / 6); retained buildings are not destroyed on population loss. Peaceful roads gate remote workshop access; closed access suspends jobs. Remote output currently returns without hauling time, explicitly tracked as incomplete.
- Renewable wood/berry/reed plots, rare paid specialist orders and owned-city goods shipments use saved simulation time only. Plots and shipments are management abstractions, not spawned farms or caravans. Specialist orders do not require roads; own-town transfers do. No autonomous resident orders or distant routing were added.
- A closed monetary base includes state/city treasuries, the regional fund and reserved payments/commissioning fees. The initial region fund is 5000; up to 100 state coins are transferred from the home treasury while preserving 40. Paid civic activities return fees to the regional market; bounded real surplus purchases fund city budgets. The invariant is checked in TickNation and save validation. This prevents accidental minting, not hoarding; no complete tax/wage policy is claimed.
- Wanderers/housing/manual relocation and infirmary/hospital treatment provide population/recovery prototypes. Inactive owned residents keep their last position. Death destroys all carried cargo/gear without coin destruction; captivity reserves it until ransom. No hero respawn occurs in the new mode.
- Save v9 stores the full state and validates counted allocations, active-view consistency, money supply and bounded entity records. Versions 1-8 retain migration backups and progression. The user explicitly requested deletion of the old local development worlds for this overhaul; setup/launch code must never repeat that cleanup automatically.

### Vessel side volume (2026-10-15)

Vessels remain procedural 2D drawings with unchanged movement/collision rules. Project heading and lateral vectors from the world plane before adding screen-vertical elevation; do not rotate an orthogonal screen-space deck footprint. Raised decks, narrower waterlines and camera-facing shaded hull walls establish volume. Rail posts and cabin walls use vertical elevation; pilots/masts sit on the deck, oar blades reach the water. Large aft cabins and folded sail faces add depth without a 3D render pass or new bitmap assets.

### Production catalogue and skill prerequisites (2026-10-15)

- The city-stock tab is named Resources. Production always exposes the full recipe catalogue; workshop selection affects availability rather than hiding incompatible recipes. Case-insensitive item-name search is UI state only and suppresses gameplay shortcuts while editing.
- CheckProduction is a read-only authoritative quote shared by catalogue rendering and QueueProduction. It reports the chosen workshop/deadline/fee and individual material quantities, skills, recipe knowledge, technologies and building/queue requirements. Only unmet requirements are muted; the overall recipe/Queue action is muted when any check fails. Item/requirement PNGs use the existing atlas; hover explains icons and unavailable recipes. Dynamic row pagination accommodates wrapped requirement rows.
- Skills() owns explicit prerequisite edges. Learning checks all ancestors as well as practice; ProgressCards uses those same edges. Resident research validates the inherited branch, and specialist teaching/projects follow the Craftsmanship prefix. Preserve older earned flags without granting new flags or resetting progress; later unlocks must still have a complete prefix. Engineering follows Construction and Trading; the tree places it to the right of Construction.
