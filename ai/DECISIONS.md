# Decisions

- The game stays native C++20 + raylib, with an isometric open world and chunk streaming.
- All player-facing content is English.
- NPC interactions are authored lore, concrete quest offers, quest turn-ins, trade and teaching. Unbounded model conversations are removed from the gameplay loop. Quest rewards and conditions are authoritative game rules.
- Clothing and weapons use counted copies. Citizen equipment is reserved from the same inventory; assigning gear does not destroy it. Player equipment changes are available anywhere. Weapon durability is intentionally absent.
- New campaigns select a starting background with real positive and negative modifiers. Existing saves use the neutral Traveler background.
- Strategic warfare stays a placeholder. Citizen jobs, equipment, training and economic contributions are implemented foundations; they must not be presented as marching armies or city conquest.
- Windowed launch is the default even if an old settings file stored fullscreen. Explicit CLI `--fullscreen` or the settings toggle can opt into fullscreen during the session.
- Keep the 60 FPS target. A p95 of 30 ms is a ceiling for richer visuals, not a deliberate frame-rate target.

- New resident research checks all requirements before spending coins. Average trust excludes owned towns so the starting town's guaranteed trust cannot bypass diplomacy. Civic charter earned through exploration unlocks higher diplomatic training.
- Existing leather armor is migrated to a counted garment with its original approximate damage reduction (12 damage → 7, 18 → 11). New heavy guard armor trades movement speed for stronger protection.
- A `--benchmark-community` scenario exercises quest turn-in, clothing copies, resident research, worker assignment, defender equipment and the existing combat/water expedition. Ordinary game sessions never make language-model requests.
- `scripts/run.sh` is the joint local launcher. Wait for a healthy server with alias `forest-npc`, preserve externally owned servers, and terminate only launched children on exit/signals. Model/server downloads and builds remain explicit setup steps. Launching the model does not restore unbounded NPC conversations.
- An explicitly supplied `--llm-port` overrides persisted menu settings, including the default value 8080. The launcher passes one port to both processes.
- Interface text uses a 1.25 multiplier over the previous minimum-16 sizing, rounded to physical integer sizes. Bake the required glyph sizes directly and snap text positions to whole pixels; avoid scaling a nearby font atlas. Wrapping and measurement use the same effective sizes.
- Lessons expose shared authoritative learned/readiness/practice state in both the hall and skills menu. Learning is a one-time unlock, not an XP level; learned lessons disable repeat actions and show completion immediately.
- Main-menu backgrounds are native raylib landscapes (forest lake, coast, town and underwater). Choose once per menu entry and avoid consecutive repeats within a process; FRONTIER_MENU_SCENE can select a scene for reproducible previews. No bitmap downloads or model generation are needed.
- ESC closes an active gameplay panel, otherwise opens/resumes pause. Paused sessions suspend player actions, combat and world/resident simulation. Pause Quit saves successfully before returning to the lobby; on write failure keep the session open for retry. ESC in the lobby never closes the application; the explicit main-menu Quit does. Interactive --play and temporary sessions also return to the lobby, while benchmark/frame-limited automation keeps its existing completion behavior.
- Movement supports both WASD and arrow keys. Combine equivalent directions as booleans before normalization so holding both bindings does not double speed. Reserve WASD for movement; town-hall/diplomacy uses P, settings application uses F5, and E talks to NPCs only, even beside a hall. Menu navigation still uses arrows.
- Saved-world and paused-world summaries share one renderer and five tabs. Inventory and knowledge use vertical rows; individual PNG icons are packed into one texture atlas. Paused summaries read current live progress and cannot teach, research, spend resources or change the player's world layer.
- The dependency graph distinguishes activity counters from learned skills, includes both research prerequisites and quest/town knowledge sources, and uses the authoritative lesson/research readiness checks. Learned cells are light green; locked cells are dark green; ready unlocks get a gold marker. Activity cards show recorded counts, with each child retaining its own threshold.
- Public setup uses scripts/install.sh for a Release game build and tests; --with-model explicitly adds CPU llama-server and the Qwen GGUF download. Keep the existing joint-launch default, with --no-model available for ordinary authored gameplay. Setup never installs system packages or replaces saves/settings. Preserve completed downloads; resume interrupted model downloads in a .part file and promote only after curl succeeds and a GGUF header is present. This is format validation, not a cryptographic checksum.
- Disable both llama.cpp UI building and prebuilt UI downloads for the server setup; the game uses its HTTP API and does not require an additional web frontend. Existing source checkouts remain user-controlled. The English README documents implemented gameplay and links to the incomplete-systems inventory rather than presenting prototypes as complete warfare or city simulation.
- Repository publication targets https://github.com/kiquxd/forest-frontier on main. Keep generated builds, downloaded dependencies/fonts/models, local saves/settings/logs and credentials out of Git; ship sources, content, icon assets and font license. Document full setup with --with-model and the smaller authored-gameplay setup separately. Custom instruction/chat GGUFs can use the same forest-npc alias and streaming API, but compatibility depends on llama.cpp support, the embedded template and current reasoning/sampling parameters; only the default Qwen model is validated.
- README Current limits is the public inventory of all incomplete systems and technical limitations, synchronized with ai/PLACEHOLDERS.md. Keep current behavior and missing parts explicit, preserve the four requested main README sections, and update public/maintainer documentation in the same implementation change. Intentional choices are not missing features; possible extensions are not promises.
